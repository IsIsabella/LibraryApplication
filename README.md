# Библиотека

Страница `/itline` - таблица со списком книг, содержащая поля: статус активности, иконка, название,
описание. Добавление новой книги происходит через модальное окно, а удаление требует подтверждения.
Работает без перезагрузки страницы (REST API, JSON).

## Запуск

Данные хранятся в PostgreSQL (Docker-том) и переживают перезапуск приложения.

```bash
docker compose up -d        # PostgreSQL 16 на localhost:5433
./mvnw spring-boot:run      # приложение на http://localhost:8080/itline
./mvnw test                 # приёмочные smoke-тесты (нужна запущенная БД)
```

## Архитектура

- **Backend:** Java 17, Spring Boot 3.5.16, Spring Data JPA/Hibernate ORM, Liquibase, Bean
  Validation.
  Слои: `BookController` (HTTP) -> `BookService` (логика, транзакции) -> `IBookRepository` (БД);
  `ApiExceptionHandler` превращает ошибки в JSON с правильным статусом (400/404/409, а не 500).

- **API:** `GET /api/books`, `POST /api/books`, `PATCH /api/books/{id}/active`,
  `DELETE /api/books/{id}?version=N`.

- **Конкурентность:** У книги есть `version` (`@Version`). Клиент передаёт версию, которую видел;
  если книгу уже изменили/удалили в другой вкладке, сервер отвечает 409/404, а не затирает чужое
  изменение. Удаление - одна атомарная операция `DELETE ... WHERE id=? AND version=?`.

- **Клиентское состояние:** Все запросы идут по очереди, UI рисуется из ответов сервера, при 
  любой ошибке или возврате во вкладку список перечитывается из БД.

- **Иконки:** SVG 32×32 в `static/icons`

## Почему такой фронтенд

Статика (HTML + CSS + JS) без сборки: экран один и простой, поэтому Node.js и фреймворки
будут избыточны. SPA-поведение сохраняется в данной архитектуре, т.к. есть `fetch` и JSON, без 
перезагрузок.
